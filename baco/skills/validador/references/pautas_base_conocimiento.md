# Pautas de redacción para la Base de Conocimiento

## Propósito y alcance

La Base de Conocimiento ofrece a clientes y finnencers información para realizar acciones, tareas y resolver problemas frecuentes del sistema. Las entradas deben ser útiles, precisas, completas y estar orientadas al usuario.

Publicar información general que pueda servir a otros usuarios. No publicar casos particulares de clientes, datos personales, información de procesos internos, bugs sin solución ni reportes internos de lo realizado para resolver un caso. No incluir enlaces sin contexto o explicación.

Antes de publicar, comprobar que la información sea apta para los lectores previstos y que pueda ayudar a resolver una necesidad general.

## Principios de redacción

- Escribir con claridad y precisión; evitar ambigüedades y vaguedades.
- Orientar el texto al usuario y explicar de forma didáctica.
- No dar por sentados conocimientos: usar nombres precisos y explicar conceptos específicos cuando sea necesario.
- Usar verbos en infinitivo para las instrucciones y los pasos.
- Evitar el uso innecesario de términos negativos, como “Error”.
- Generalizar el caso: describir las acciones y condiciones que pueden repetirse, no las particularidades de una persona o cliente.

## Título

El título debe describir la acción y el área o contexto. Usar verbos en infinitivo. Agregar un subtítulo con palabras clave o el nombre o número del problema, separado con un guion o dos puntos. Ser específico, incluir el problema y evitar repeticiones o palabras redundantes.

- **Evitar fórmulas interrogativas o redundantes:** No iniciar títulos con “Cómo…”, “Cómo hacer para…” ni construcciones similares; comenzar directamente con la acción en infinitivo (ej. *“Configurar facturación electrónica…”*, no *“Cómo configurar…”*).
- **Tratamiento de la palabra “Error”:** Usar “Error” única y exclusivamente cuando forme parte textual del mensaje o código devuelto por el sistema (citado textualmente entre comillas o tras dos puntos). Evitar el término en títulos genéricos de instructivos o soluciones. Para más detalles y ejemplos, consultar [Cómo escribir buenos títulos](como_escribir_buenos_titulos.md).

## Categoría y etiquetas

- Seleccionar la categoría correspondiente al frente, industria o módulo de negocio.
- Elegir etiquetas que identifiquen la acción, las palabras clave y el tipo de publicación.
- Incluir siempre `instructivo` o `soluciones` entre las etiquetas, según el tipo de plantilla. Si la persona no lo proporciona, agregar la etiqueta correspondiente.
- Estos campos son obligatorios en la publicación.

## Cuerpo de la entrada

Elegir la plantilla adecuada para el tipo de contenido. Una entrada de solución debe incluir **Consulta** y **Pasos a seguir**. Cuando la causa esté confirmada, se puede añadir debajo de la consulta una explicación breve que adelante la solución, sin crear una sección separada **Respuesta**. No inferir causas que no estén respaldadas por la fuente.

### Consulta

Describir en tiempo presente qué sucede, dónde o cuándo ocurre, qué acciones llevan a esa situación y qué mensaje aparece. Indicar la ruta de acceso o los componentes involucrados. Separar los elementos de la ruta con flechas.

**Ejemplo de ruta:** `Menú → Gestión Empresarial → Compras → Proveedores`

Cuando se incluya un mensaje o número de error, conservar su texto exacto entre comillas para facilitar la búsqueda. Explicar el contexto necesario y eliminar detalles particulares del caso.

La explicación de la causa y la solución confirmadas debe integrarse como un párrafo breve dentro de **Consulta**. No crear una sección separada **Respuesta**.

### Pasos a seguir

Indicar desde qué ruta, solapa, pestaña o acción comienza la solución. Enumerar las acciones en orden cronológico y redactarlas como instrucciones en infinitivo.

1. [Primera acción].
2. [Segunda acción].
3. [Tercera acción].

Si hay más de una solución, separarlas en opciones claramente identificadas. Usar capturas de pantalla cuando ayuden a mostrar mensajes, campos o controles relevantes; intercalar cada imagen con el texto que la explica.

### Requiere AppBuilder

Incluir esta indicación solo cuando los pasos requieran AppBuilder o Tipos de Documentos y el usuario necesite ese permiso. Si no aplica, eliminarla.

## Revisión antes de publicar

- Revisar ortografía, gramática y puntuación en el título, la categoría, las etiquetas y el cuerpo.
- Acortar o dividir oraciones demasiado largas.
- Evitar abreviaturas innecesarias o que el lector pueda desconocer.
- Confirmar que la entrada sea clara, completa, precisa y útil para el usuario.
- Verificar que la información sea apta para publicarse para los lectores previstos; la Base de Conocimiento es visible públicamente.
