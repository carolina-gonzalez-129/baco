# Cómo escribir buenos títulos

## Estructura recomendada

El título debe identificar el tema, la acción y el área o contexto. Para detallar el problema, agregar un subtítulo con palabras clave o con el nombre o número del mensaje. Separar título y subtítulo con un guion o dos puntos.

Usar los verbos en infinitivo cuando el título describe una acción. Para títulos de documentación general de producto, se puede usar un sintagma nominal.

**Formato sugerido:** `[Acción en infinitivo] - [Área o contexto]: [mensaje o detalle]`

**Ejemplo:** `Obtener CAE - Mensaje AFIP: “Imposible conectar con webservice”`

La primera parte nombra la acción; el subtítulo incorpora el mensaje textual que recibió el usuario.

## Mensajes del sistema

- Se puede usar “Mensaje”, “Aviso” o “Advertencia” para presentar lo que muestra el sistema.
- Usar la palabra “Error” solo cuando aparezca en el mensaje original del sistema.
- Mantener el texto del mensaje fiel al original cuando se lo incluya entre comillas.

## Criterios de calidad

- Ser específico e incluir el problema en el título.
- Iniciar directamente con verbos en infinitivo; **no usar fórmulas redundantes** como “Cómo...”, “Cómo hacer para...” o “Pasos para...”.
- Evitar repetir palabras.
- Evitar palabras redundantes, como “instructivo” o una palabra que ya está indicada por la categoría.
- No redactar el título como una narración extensa del caso; nombrar la acción y el problema directamente.

## Ejemplos de acciones o problemas

- `Guardar una cobranza - Aviso: “Falta especificar un workflow”`
- `Crear chequera nueva - Mensaje: “Error de código duplicado: Otra entidad con el mismo código ha sido ingresada anteriormente”`
- `DAI Builder - Crear campos adicionales en maestros`

## Títulos de documentación general

- `Lista de precios de venta`
- `Planificación agrícola - Documento de Alcance`
- `Maestro de Productos`
